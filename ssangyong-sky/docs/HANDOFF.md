## 이메일 수신 설정 — 운영자 작업 필요

기존 전포 페이지에 Web3Forms access_key가 있으나 그 키의 수신자가 `1906interior@naver.com`이라는 근거는 확인되지 않았습니다. 새 페이지에 키를 복제하지 않았고 수신 설정 완료로 처리하지 않았습니다.

1. [Web3Forms](https://web3forms.com/)에서 `1906interior@naver.com`을 인증하고 해당 폼의 공개 access key를 확인/발급합니다. 네이버 비밀번호, 비밀 관리 API 키는 공유하거나 코드에 넣지 않습니다.
2. `data.js`의 contact.accessKey에 **공개 form access key**를 입력합니다. 관리자 화면에서 수신 주소를 확인한 뒤 recipientVerified:true로 설정합니다. recipient 문자열을 변경하는 것만으로 메일 수신자가 바뀌지 않습니다. 수신은 서비스의 키 설정이 결정합니다.
3. 보유기간을 확정해 contact.retention에 안내문을 입력하고 최종 개인정보 안내를 검토한 뒤 privacyApproved:true로 설정합니다. 네 조건이 모두 충족되어야 제출 가능합니다.
4. 서비스에서 제공하는 도메인 제한/스팸 설정을 확인합니다. 클라이언트 허니팟만으로 모든 스팸을 방지할 수는 없습니다.
5. 사용자 승인 후 실제 공개 주소에서 테스트용 비민감 내용으로 **한 번** 제출합니다. 이 작업에서는 실제 이메일을 보내지 않았습니다.
6. 서비스 접수 성공, 네이버 받은편지함/스팸함 도착을 각각 기록합니다. 제목의 선택 타입, 본문의 이름/정규화 연락처/아파트명/평형 포함 타입/문의/한국 시간을 대조합니다. 지연/실패 시 서비스 대시보드를 확인합니다.

공식 근거: [Web3Forms 설치](https://docs.web3forms.com/getting-started/installation), [FAQ: access key와 수신 이메일](https://docs.web3forms.com/getting-started/faq).

## GA4 — 구현 상태와 계정 설정 구분

- 최신 main의 전포·서면쌍용 안내 페이지 모두 `G-BH516Y53QM` 사용을 확인했습니다.
- [제공된 관리 화면](https://analytics.google.com/analytics/web/#/a401079771p545484992/reports/intelligenthome)은 로그인 화면으로 연결되었습니다. 속성 `545484992`와 측정 ID의 계정 내 연결 관계는 **확인 필요**입니다. 계정 설정 변경은 수행하지 않았습니다.
- 새 페이지는 config send_page_view:false 후 명시적 page_view 1회. 모든 수동 이벤트에 apartment_id:ssangyong_sky, 해당 이벤트에 type_id를 전달합니다.
- URL은 고정 페이지 경로와 정확히 일치하는 3개 QR UTM만 전달합니다. 임의 query/hash, 전체 referrer, 폼 내용은 전달하지 않습니다. referrer는 origin만 사용합니다.
- 로컬에서는 dataLayer 큐만 검증하고 GA 스크립트를 로드하지 않습니다. 운영 스크립트는 interiorhipo.github.io에서만 1회 삽입됩니다.
- 초기 렌더는 select_apartment_type으로 집계하지 않습니다. view_design_image는 확대를 열 때, click_phone은 전화 링크 클릭일 뿐 통화 완료가 아닙니다. generate_lead는 서비스 접수 성공 수이며 실제 메일 도착/상담 완료 수가 아닙니다.

### 운영자가 해야 할 GA 설정

1. 관리 → 데이터 스트림 → 웹 스트림에서 측정 ID `G-BH516Y53QM`과 대상 사이트를 확인합니다. 다른 ID를 임의로 생성하지 마세요.
2. 관리 → 맞춤 정의에서 **이벤트 범위** 맞춤 측정기준을 만듭니다: `apartment_id`, `type_id`. 필요하면 `image_index`도 등록합니다. [Google 공식 안내](https://support.google.com/analytics/answer/14240153).
3. 관리 → 이벤트/주요 이벤트에서 `generate_lead`를 주요 이벤트로 표시합니다. 속성 전체 이벤트이므로 타 페이지의 같은 이벤트도 포함됩니다. 서면쌍용 보고서에서 apartment_id 필터를 사용합니다.
4. 웹 스트림의 향상된 측정/Google 태그 설정을 검토해 자동 폼 상호작용이 의도치 않은 추가 이벤트를 만들지 않는지 확인합니다. 이 작업에서는 기존 스트림 설정을 바꾸지 않았습니다.
5. 배포 승인 후 Tag Assistant/DebugView에서 페이지 진입 1회, QR 이벤트 1회, 사용자 타입 선택/확대/전화 클릭을 확인합니다. 실제 상담 테스트를 승인한 경우에만 generate_lead를 확인합니다. 실제 GA 수신은 이 작업에서 확인하지 않았습니다.
